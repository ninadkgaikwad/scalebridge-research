# Phase C General Runner Option Coverage

This record documents the runner-first contract introduced before the BGIRS Phase C Dash tabs.

## Contract rule

`PhaseCCampaignConfig` is the single public, scientific-neutral configuration contract. The Dash Campaign Builder must consume this contract; the Execution tab must invoke `run_phase_c_campaign.py`; Dash callbacks must not bypass the runner to reach lower-stage options.

## Promoted public option families

| Family | Current owning stages | General runner coverage |
|---|---|---|
| Parent/run identity | C1/C9 | campaign root or campaign ID + generated-data root, matrix run, Phase C run ID; expert C1-only direct aggregation-run root |
| Scientific scope | C1-C8 | case, aggregation ID, weight mode, aggregate zone, repeatable model IDs where supported |
| Feature/target construction | C1-C2 | minimum sample count, internal-gain predictor method, HVAC target method, preview rows |
| Split construction | C3 | strategy, train/validation/test fractions, minimum samples, fraction tolerance, persisted seed, preview rows |
| Dataset construction | C4 | minimum split samples, model filters, preview rows |
| Model API validation | C5 | C4 model limit, PyTorch skip, repeatable PyTorch validation devices |
| Training | C6 | estimators, devices, expert fit-intercept override, ridge, learning rate, epochs, tolerance, patience, seed, reload tolerances, preview rows |
| Evaluation | C7 | artifact/model filters, optional requested-device recovery filter, full-prediction policy, preview rows |
| Annual inference | C8 | artifact/model filters, optional requested-device recovery filter, preview rows, overwrite where implemented |
| Validation thresholds | C2-C8 | all currently implemented feature/timestamp/split/dataset/training/evaluation/inference tolerances and expected canonical cadence/count settings |
| MLflow registration | C9 | enabled, validation mode, experiment/run names, strictness, compact/model artifact logging, artifact-size limit |
| Diagnostics | post-C8 | optional missing-value root-cause audit and residual-gap audit using existing scripts |

## Intentionally runner-owned / not public knobs

The following stage CLI arguments remain internal because they are provenance/path plumbing rather than scientific campaign choices:

- stage output roots;
- C1-C8 run IDs generated from the shared Phase C timestamp suffix;
- C1-C8 manifest override paths used by standalone C9 recovery;
- C9 `registration_output_dir`;
- source-syntax validator path lists;
- C9 expected task counts, which are derived from completed manifests/registration state;

## Important corrections to the previous runner

1. `--max-zones` previously existed at the top level but was silently skipped because C1 did not expose a matching option. C1 now implements real post-discovery truncation.
2. `--overwrite-existing` is routed only to stages whose current CLIs implement explicit overwrite semantics (C6 and C8). Unique Phase C run IDs remain the normal protection for earlier stages.
3. C7/C8 no longer inherit PyTorch requested-device filtering automatically. That filter can incorrectly hide closed-form artifacts in mixed-estimator campaigns; artifacts generated by the selected C6 run are therefore consumed without an unnecessary device filter.
4. C6/C7/C8 run directory names are estimator-neutral (`c6_models_*`, `c7_models_*`, `c8_models_*`) while preserving the shared timestamp suffix used by C9 discovery.

## UI consequence

Future BGIRS tabs should not maintain a second independent scientific option list. The Campaign Builder should use `PhaseCCampaignConfig` schema/capability metadata, and Execution should use the same normalized JSON or equivalent CLI overrides.

## Exhaustive lower-level CLI audit

The Step 0 audit classifies every long-form option currently declared by the C1-C9 stage scripts, validators, and the two existing C8 diagnostic scripts (excluding the generalized runner itself):

- **83 distinct lower-level long-form options audited**;
- **63 are public scientific/scope/execution/validation/tracking capabilities** represented by `PhaseCCampaignConfig` and/or normalized runner controls;
- **20 are deliberately runner-owned provenance/path/derived-validation arguments** and are listed exactly in `capability_manifest()["internal_only_cli_options"]`.

A regression test parses the lower-level scripts with Python AST and fails if a future CLI option appears without being added to one of those two classifications. This prevents the Dash UI and the generalized runner contract from silently drifting behind the scientific implementation.

The C6-C8 repeatable `--aggregate-zone-id` capability is preserved through the expert `downstream_aggregate_zone_ids` recovery filter. The normal `aggregate_zone_id` remains the single upstream C1-C4 scope filter. If an upstream single-zone filter is used, the downstream filter is forbidden from broadening it.

Configuration-file booleans also have symmetric CLI overrides. For example, `continue_on_error`, `overwrite_existing`, C5 PyTorch skipping, C2 conflict failure, MLflow enablement/artifact policy, and optional C8 diagnostics can all be explicitly turned on **or** off from the CLI after loading a JSON configuration.
