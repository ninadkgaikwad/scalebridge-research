\begin{abstract}
This document supersedes the E0-6 v1 mathematical contract and freezes the
revised E0-6 authority for representing one compiled linear resistance--
capacitance (RC) thermal graph in multiple computational backends while keeping
\emph{physical model coordinates} separate from \emph{estimation coordinates}.
E0-3 remains the authority for RC flavours, topology, physical parameter
vocabulary, sharing, and routing semantics; E0-4 remains the authority for
runtime state and canonical forcing; and E0-5 remains the authority for
fixed-step ZOH discretization/integration.

The central v2 correction is
\[
\boxed{\text{RC physics }\Theta\;\neq\;\text{parameter-estimation coordinates}.}
\]
All physics-based methods must agree at a common physical master-parameter
vector $\Theta$, but they need not optimize the same coordinates. PyTorch/
Neuromancer scientific-machine-learning methods may use unconstrained raw
coordinates $\rho$ with differentiable physical transforms
$\Theta=\mathcal T(\rho)$. In contrast, the production CasADi/IPOPT path for
deterministic grey-box parameter estimation is authorized to use the physical
RC master parameters directly as nonlinear-program decision variables with
explicit variable bounds and equality/inequality constraints. A transformed-
$\rho$ CasADi realization is retained only as an optional parity/reference
coordinate system, not as the mandatory production optimization interface.
NumPy receives physical $\Theta$ directly and serves as the independent
numerical RC forward-model/reference backend, including the default likelihood
engine for non-gradient Bayesian RC estimation. Future gradient-based Bayesian
methods may use another autodifferentiable backend without changing the
physical authority.

The contract is graph-general and zone-count-general. For any current registered
E0-3 flavour (1R1C, 2R2C, 3R2C, or 4R3C), any finite number of zones, any valid
E0-3 spatial coupling, and any future compiler-valid linear RC flavour, E0-6
constructs the same physical matrices and continuous/discrete equations from
$\Theta$. Flavour-specific routing remains E0-3 compiler metadata. For the
current paper-compatible 2R2C semantics,
\[
Q_c=Q_{AC}+Q_{ZIC}+Q_{Sol1},\qquad
Q_r=Q_{ZIR}+Q_{Sol2},
\]
with $Q_{ZIR}$ and $Q_{Sol2}$ sharing the flavour-defined radiative fraction
$\eta_r$.

The authoritative physical parity statement is therefore
\[
\boxed{
\Theta_N=\Theta_T=\Theta_{NM}=\Theta_C
\Longrightarrow
f_N=f_T=f_{NM}=f_C
}
\]
within frozen numerical tolerances, together with parity of derived matrices,
state/input Jacobians, physically comparable parameter sensitivities, and
common discrete propagation. When comparing PyTorch raw-coordinate gradients to
CasADi physical-coordinate gradients, E0-6 uses the chain rule rather than
incorrectly equating gradients taken in different coordinates.
\end{abstract}

\paragraph{v2 supersession statement.}
E0-6 v2 supersedes v1 wherever v1 stated or implied that all production
backends must use one common raw optimization vector $\rho$. The v1 physical
transforms remain valid for PyTorch/Neuromancer and for optional transformed
reference adapters; the physical RC equations, current heat-input semantics,
DEP2 conservation mathematics, graph assembly, exact-ZOH oracle, and numerical
tolerances remain unchanged unless explicitly revised below.

\section{Scientific and software provenance}

Thermal-network state-space construction from thermal circuits and RC networks
is standard in building thermal modelling and is the basis of the already-frozen
E0-3 contract \cite{GhiausAhmad2020ThermalCircuits,BacherMadsen2011HeatDynamics,
ArroyoSpiessensHelsen2020MultiZone,VallianosAthienitisDelcroix2022MultiZoneRC}.
The E0-5 exact linear zero-order-hold propagation follows standard matrix-
exponential theory \cite{Higham2009MatrixExponential,VanLoan1978MatrixExponentialIntegrals}.

Automatic differentiation (AD) evaluates exact derivatives of implemented
numerical programs up to floating-point effects by systematically applying the
chain rule \cite{Baydin2018AD}. PyTorch provides imperative tensor computation,
registered model parameters, automatic differentiation, and matrix-exponential
operations \cite{Paszke2019PyTorch,PyTorchParameterDocs2026,PyTorchMatrixExpDocs2026}.
Neuromancer is a PyTorch-based differentiable programming and scientific-machine-
learning framework and exposes ODE abstractions used by the E0-5 integrator layer
\cite{Neuromancer2023,NeuromancerDocs2026}. CasADi provides symbolic expression
graphs, algorithmic differentiation, ODE/DAE tools, and nonlinear/optimal-control
interfaces \cite{Andersson2019CasADi,CasADiDocs2026}. CasADi's nonlinear-
program interface exposes direct decision-variable bounds and general equality/
inequality constraints, and IPOPT implements a primal--dual interior-point
filter line-search method for nonlinear programming
\cite{WachterBiegler2006IPOPT,CasADiDocs2026}. NumPy provides the
independent array-computing numerical reference \cite{Harris2020NumPy}.

Simplex-valued compositions and log-ratio coordinates are classical objects in
compositional-data analysis \cite{Aitchison1982Compositional}. E0-6 uses this
background only as mathematical motivation: the centered anchored-softmax
parameterization defined below, the exact choice of anchor, the centered
baseline, the DEP2 contribution-simplex variable $p_i=w_i\lambda_i$, the
cross-backend tolerance profiles, and the parity ladder are explicitly
\SB{}-defined design choices.

\section{E0-6A: Authority boundary and graph generality}

E0-3 defines the compiled continuous thermal graph. E0-4 defines valid runtime
state and canonical forcing. E0-5 defines numerical time advancement. E0-6 owns
only backend-native parameter realization, admissible trainable coordinates,
and numerical/derivative parity:
\[
\boxed{\text{E0-3: graph physics and continuous RHS}}
\]
\[
\boxed{\text{E0-4: runtime state and canonical forcing realization}}
\]
\[
\boxed{\text{E0-5: fixed-step ZOH numerical evolution}}
\]
\[
\boxed{\text{E0-6: physical backend realization, coordinate policies, parity}}
\]

Let the compiled model be
\[
\mathcal G_c=
(\kappa_X,\kappa_B,\kappa_Q,
\mathcal E_{CC},\mathcal E_{CB},
\mathcal S_{share},\mathcal S_{route},H,\mathcal P),
\]
where $\kappa_X,\kappa_B,\kappa_Q$ are deterministic state/boundary/thermal-port
orders; $\mathcal E_{CC}$ and $\mathcal E_{CB}$ are graph edges;
$\mathcal S_{share}$ identifies master-parameter sharing; $\mathcal S_{route}$
defines compiler-approved routing bases/support; $H$ is the immutable observation
matrix; and $\mathcal P$ is physical-parameter metadata.

For arbitrary dimensions
\[
n_x=|\kappa_X|,\qquad n_b=|\kappa_B|,\qquad n_q=|\kappa_Q|,
\]
E0-6 operates on the same generic matrix shapes
\[
C\in\R^{n_x\times n_x},\quad
L_{CC}\in\R^{n_x\times n_x},\quad
L_{CB}\in\R^{n_x\times n_b},\quad
\Gamma\in\R^{n_x\times n_q}.
\]
No E0-6 equation depends on a fixed number of zones or a fixed RC flavour.

\begin{proposition}[Zone-count and topology generality]
If an E0-3 compiler emits a valid linear RC graph satisfying the E0-3
invariants, then the E0-6 parameter transforms, master-parameter expansion,
incidence/selector matrix construction, continuous RHS, derivative oracles, and
backend parity definitions apply without modification for any finite $n_x,n_b,n_q$.
\end{proposition}

\paragraph{ScaleBridge design implication.}
Flavour-specific knowledge such as ``current 2R2C radiative gains share
$\eta_r$'' belongs in $\mathcal S_{route}$. E0-6 does not contain hard-coded
branches such as ``if flavour is 2R2C'' in its generic algebra.

\section{E0-6B: One physical model, multiple computational backends}

Define the authoritative backend family
\[
\boxed{\mathbb B=\{N,T,NM,C\}},
\]
where $N$ is NumPy, $T$ is PyTorch, $NM$ is Neuromancer/PyTorch, and $C$ is
CasADi. The backend authority is defined in \emph{physical master-parameter
space}. Let $\kappa_\Theta$ be the deterministic ordering of independent
physical master parameters authorized by the selected E0-3 flavour, spatial
compiler, sharing policy, and DEP2 allocation policy. Then
\[
\boxed{\Theta\in\mathcal D_\Theta\subseteq\mathbb R^{n_\Theta}}
\]
is the common physical point.

For backend $b\in\mathbb B$, let
\[
\mathcal R_b(\mathcal G_c,\Theta)
\]
be the backend-native physical realization. E0-6 requires
\[
\boxed{
\Theta_N\equiv\Theta_T\equiv\Theta_{NM}\equiv\Theta_C
}
\]
at parity probes, and therefore requires parity of all derived physical
quantities, matrices, RHS values, and common discrete propagation within the
frozen tolerances.

An estimation algorithm may introduce its own coordinates $\zeta_b$ and a map
\[
\Theta=\mathcal T_b(\zeta_b).
\]
The map is an algorithm/backend policy and is not the physical model itself.
In particular:
\[
\boxed{
\zeta_T=\zeta_{NM}=\rho\quad\text{for transformed SciML training},
}
\]
while the production CasADi/IPOPT path may use
\[
\boxed{\zeta_C=\Theta}
\]
directly. Neuromancer is not an independent physical model: it reuses the
PyTorch physical parameter owner and wraps its RHS in the Neuromancer ODE API.

\section{E0-6C: Immutable semantics versus trainable physics}

Partition the compiled authority as
\[
\boxed{\mathcal G_c=(\mathcal K,\Theta)},
\]
where $\mathcal K$ contains immutable semantics and $\Theta$ contains physical
quantities. Immutable semantics include state ordering, boundary ordering,
thermal-port ordering, graph adjacency, parameter-sharing maps, routing support,
observation matrix $H$, and structural zero patterns.

Candidate trainable physical master quantities include positive capacitances,
positive resistances, bounded routing parameters, and compiler-approved DEP2
allocation parameters. Derived matrices and quantities are never independent
optimizer variables:
\[
\boxed{L_{CC},L_{CB},A,B_T,B_Q,g,H\ \text{are derived/immutable as appropriate}.}
\]
In particular, resistance and conductance are never trained simultaneously.

\section{E0-6D: Physical master coordinates and estimation-coordinate policies}

The canonical cross-method authority is the deterministic physical master vector
\[
\boxed{\Theta=[\theta_1,\ldots,\theta_{n_\Theta}]^{\mathsf T}}
\]
with ordering $\kappa_\Theta$. It contains only independent free physical master
quantities: fixed parameters remain part of the physical model but are not
optimization decision variables; shared occurrences appear once at the master
level; conductances and matrices remain derived.

For transformed-gradient training, define a dimensionless raw coordinate vector
\[
\boxed{\rho\in\mathbb R^{n_\rho}}
\]
for the subset of trainable master degrees of freedom and a centered map
\[
\boxed{\Theta_{train}=\mathcal T(\rho;\Theta^{(0)},\mathcal P)},
\qquad
\boxed{\rho=0\Longrightarrow\Theta_{train}=\Theta_{train}^{(0)}}.
\]
The raw ordering $\kappa_\rho$ is deterministic and derives from
$\kappa_\Theta$ plus the campaign fixed/trainable/shared policy.

For production deterministic optimization with CasADi/IPOPT, the authorized
primary coordinate is the physical decision vector itself:
\[
\boxed{z_{NLP}=\Theta_{free}^{phys}.}
\]
Physical admissibility is then enforced by NLP variable bounds and explicit
constraints rather than by requiring $\Theta=\mathcal T(\rho)$.

Thus E0-6 freezes two distinct concepts:
\[
\boxed{\kappa_\Theta=\text{common physical meaning/order}}
\]
versus
\[
\boxed{\kappa_\rho=\text{one transformed training coordinate system}.}
\]
No scientific parity claim may equate coordinates having different meanings.

\section{E0-6E: Transformed-coordinate policy for PyTorch/Neuromancer}

The transforms in this section are the default ScaleBridge policy for
unconstrained-gradient SciML training and for optional transformed-reference
adapters. They are \emph{not} mandatory for the production physical-coordinate
CasADi/IPOPT NLP.

\subsection{Strictly positive parameters}
For a positive parameter $p$ with baseline $p^{(0)}>0$,
\[
\boxed{p(\rho)=p^{(0)}e^{\rho}.}
\]
More generally, for strict lower bound $\ell$,
\[
\boxed{p(\rho)=\ell+(p^{(0)}-\ell)e^{\rho},\qquad p^{(0)}>\ell.}
\]
This structurally preserves positivity during unconstrained gradient updates and
avoids post-update clipping.

\subsection{Finite physical interval}
For $\ell<p<u$ and $\ell<p^{(0)}<u$, define
\[
a_0=\logit\left(\frac{p^{(0)}-\ell}{u-\ell}\right)
\]
and
\[
\boxed{p(\rho)=\ell+(u-\ell)\sigmoid(a_0+\rho).}
\]
Then $p(0)=p^{(0)}$.

\subsection{Fixed and unrestricted parameters}
A fixed quantity has no trainable raw coordinate. A compiler-approved
unrestricted parameter may use
\[
\boxed{p(\rho)=p^{(0)}+s_p\rho,\qquad s_p>0.}
\]
Current standard RC resistances/capacitances do not use this unrestricted family.

\subsection{Physical-coordinate optimization counterpart}
The same positive or bounded physical parameter may instead be an IPOPT decision
variable $p$ with
\[
\boxed{\ell_p\le p\le u_p}
\]
(or only a one-sided bound where appropriate). Bounds are part of the NLP domain,
not an additional physical model. CasADi exposes decision-variable bounds and
nonlinear constraint bounds directly, and its Opti interface can pass simple
constant bounds efficiently to IPOPT \cite{CasADiDocs2026}.

\section{E0-6F: Simplex routing, structural zeros, and dual coordinate forms}

Let thermal port $s$ have compiler-approved receiving-state support
$\mathcal I_s$. A routing composition obeys
\[
\gamma_{i,s}\ge0,\qquad
\sum_{i\in\mathcal I_s}\gamma_{i,s}=1,\qquad
\gamma_{i,s}=0\ \text{for }i\notin\mathcal I_s.
\]
Structural zeros are topology and remain exact zeros in every coordinate system.

For transformed PyTorch/Neuromancer training, a trainable routing group with
strictly positive baseline composition $\gamma_s^{(0)}$ uses an anchored
centered softmax. Choose deterministic anchor $a_s$, fix its raw offset to zero,
and train $|\mathcal I_s|-1$ raw coordinates:
\[
\boxed{
\gamma_{i,s}=
\softmax_i(\log\gamma_s^{(0)}+\rho_s).
}
\]
Simplex/log-ratio thinking is classical \cite{Aitchison1982Compositional}; the
centered baseline and anchor are ScaleBridge-specific.

For physical-coordinate CasADi/IPOPT optimization, the same routing composition
may be represented directly by its independent physical entries with constraints
\[
\boxed{\gamma_{i,s}\ge0,\qquad \mathbf 1^{\mathsf T}\gamma_s=1.}
\]
An implementation may eliminate one physical entry or retain the complete
composition plus the equality constraint; both represent the same physical
simplex. E0-6 parity is assessed after reconstruction of the same $\gamma_s$, not
by equating softmax logits with physical simplex entries.

\section{E0-6G: Current five-channel thermal semantics and generic routing basis}

The canonical thermal signals remain separately identified because provenance,
availability, DEP2 allocation, diagnostics, and uncertainty can differ:
\[
\boxed{Q_{AC},Q_{ZIC},Q_{ZIR},Q_{Sol1},Q_{Sol2}.}
\]
PHVAC is electrical auxiliary information and is excluded from the thermal RHS.

For the current paper-compatible 2R2C family,
\[
\boxed{Q_c=Q_{AC}+Q_{ZIC}+Q_{Sol1}},\qquad
\boxed{Q_r=Q_{ZIR}+Q_{Sol2}}.
\]
Let $e_a,e_m$ select zone air/mass states. Then
\[
\boxed{\gamma_{AC}=\gamma_{ZIC}=\gamma_{Sol1}=e_a}
\]
and
\[
\boxed{
\gamma_{ZIR}=\gamma_{Sol2}=(1-\eta_r)e_a+\eta_r e_m,
\qquad 0<\eta_r<1.
}
\]
Thus QZIR and QSol2 share one flavour-defined physical master fraction
$\eta_r$.

This is a concrete realization of the generic E0-3 routing authority. The
currently registered flavour library contains 1R1C, 2R2C, 3R2C, and 4R3C, each
with its own frozen state/edge/parameter/routing schema. E0-6 consumes that
compiler metadata rather than re-defining flavour equations. Abstractly,
\[
\boxed{\Gamma=\Gamma(\mathcal S_{route},\Theta_{route}).}
\]
A new compiler-valid linear RC flavour may expose another routing basis without
changing the backend algebra.

\section{E0-6H: DEP2 contribution-simplex parameterization}

For DEP2 group $g$, the frozen aggregation row is
\[
A_g=[w_1,\ldots,w_N],
\]
and the coordinate-preservation condition is
\[
\boxed{A_gB_g=\sum_iw_i\lambda_i=1.}
\]
Define contribution variables
\[
\boxed{p_i=w_i\lambda_i},\qquad \boxed{\sum_i p_i=1}.
\]
E0-6 therefore treats $p$ as the physically meaningful allocation composition
and derives
\[
\boxed{\lambda_i=p_i/w_i\quad(w_i>0).}
\]
Zero-weight entries are outside the trainable support and receive $\lambda_i=0$.
The neutral baseline remains
\[
\lambda_i^{(0)}=\frac{1}{\sum_jw_j},\qquad
p_i^{(0)}=\frac{w_i}{\sum_jw_j}.
\]

For PyTorch/Neuromancer transformed training, $p$ uses the anchored centered
softmax. For physical-coordinate CasADi/IPOPT optimization, $p_i$ may be direct
NLP decision variables with
\[
\boxed{p_i\ge0,\qquad\sum_i p_i=1,}
\]
which structurally implies $A_gB_g=1$ after $\lambda_i=p_i/w_i$.
Different non-HVAC channels may have distinct maps
$B_{ZIC},B_{ZIR},B_{Sol1},B_{Sol2}$. QAC remains local and is never DEP2-
back-allocated.

\section{E0-6I: Spatial allocation versus within-zone state routing}

Two allocation operations are distinct and ordered:
\begin{enumerate}[leftmargin=*]
\item \textbf{DEP2 spatial allocation:} aggregate non-HVAC coordinate $\bar Q_s$
becomes per-zone source values through $B_s$.
\item \textbf{RC-state routing:} each per-zone source enters compiler-approved
thermal states through $\Gamma$.
\end{enumerate}
Symbolically,
\[
\bar Q_s\xrightarrow{B_s}Q_{s,1:N}
\xrightarrow{\Gamma_s}Q_{state}.
\]
These mechanisms must not share parameters unless the compiler explicitly says
so.

\section{E0-6J: Exact master-parameter sharing}

Let $\theta^M$ denote master physical parameters and $M$ a zero-one gather/
selector matrix with exactly one selected master per physical occurrence. Then
\[
\boxed{\theta^{inst}=M\theta^M.}
\]
For capacitances and resistance occurrence groups,
\[
c=M_Cc^M,\qquad
r_{CC}=M_{R,CC}r_R^M,\qquad
r_{CB}=M_{R,CB}r_R^M.
\]
This applies equally to shared routing master parameters such as current 2R2C
$\eta_r$ used by both $Q_{ZIR}$ and $Q_{Sol2}$.

No backend creates duplicate trainable variables and later penalizes their
difference. Sharing is structural and exact.

\section{E0-6K: Conductance and generic graph-matrix reconstruction}

For every resistance occurrence,
\[
\boxed{g_e=1/R_e.}
\]
Conductance is derived and never separately optimized.

Choose any deterministic orientation for state--state edges and let
\[
D_{CC}\in\{-1,0,1\}^{n_{ECC}\times n_x}
\]
be the oriented incidence matrix. Let
\[
G_{CC}=\diagmat(g_{CC}).
\]
For state--boundary edges, let
\[
P_X\in\{0,1\}^{n_{ECB}\times n_x},\qquad
P_B\in\{0,1\}^{n_{ECB}\times n_b}
\]
select state and boundary endpoints, with
\[
G_{CB}=\diagmat(g_{CB}).
\]
Then
\[
\boxed{
L_{CC}=D_{CC}^{\mathsf T}G_{CC}D_{CC}
+P_X^{\mathsf T}G_{CB}P_X
}
\]
and
\[
\boxed{
L_{CB}=-P_X^{\mathsf T}G_{CB}P_B.
}
\]
This construction is adapted from standard network/Laplacian thermal-circuit
formulations \cite{GhiausAhmad2020ThermalCircuits} and exactly matches the frozen
E0-3 sign convention
\[
C\dot X=-L_{CC}X-L_{CB}T_B+\Gamma Q.
\]

The capacitance matrix is
\[
\boxed{C=\diagmat(c).}
\]
and $H$ remains immutable.

\section{E0-6L: State-space matrices without a dense inverse}

Because $C$ is positive diagonal, define row-scaling vector
\[
d_C=[1/c_1,\ldots,1/c_{n_x}]^{\mathsf T}.
\]
Then
\[
\boxed{A=-\diagmat(d_C)L_{CC}},
\]
\[
\boxed{B_T=-\diagmat(d_C)L_{CB}},
\]
and
\[
\boxed{B_Q=\diagmat(d_C)\Gamma.}
\]
No backend forms a generic dense numerical inverse of $C$.

The column-vector continuous RHS is
\[
\boxed{
f(x,T_B,Q;\Theta)=A(\rho)x+B_T(\rho)T_B+B_Q(\rho)Q.
}
\]
Equivalently,
\[
\boxed{
f=\diagmat(1/c)
\left[-L_{CC}x-L_{CB}T_B+\Gamma Q\right].
}
\]

\section{E0-6N: Backend-native ownership and method-family mapping}

\subsection{NumPy physical backend}
NumPy receives physical $\Theta$ directly, reconstructs the same matrices and
RHS numerically, and owns no AD graph. It is the independent physical reference
backend \cite{Harris2020NumPy}. For Bayesian RC estimation, this NumPy physical
forward model is the default likelihood engine for samplers that require only
numerical likelihood/posterior evaluations. E0-6 does not prohibit a future
AD-enabled Bayesian backend when a gradient-based sampler requires derivatives.

\subsection{PyTorch physical-plus-transformed backend}
PyTorch owns raw trainable coordinates $\rho$ as registered parameters for
SciML methods that estimate physical RC parameters. The physical vector
$\Theta_T=\mathcal T(\rho)$ and all derived matrices remain connected to
$\rho$ through autograd. No detach, NumPy conversion, or scalar extraction is
allowed in the trainable forward path \cite{Paszke2019PyTorch,
PyTorchParameterDocs2026}.

\subsection{Neuromancer}
Neuromancer reuses the same PyTorch physical parameter owner and wraps the same
RHS in the Neuromancer ODE API. It does not duplicate $\rho$ or $\Theta$
\cite{Neuromancer2023,NeuromancerDocs2026}.

\subsection{CasADi physical backend for deterministic optimization}
The production optimization adapter exposes physical master decision variables
$\Theta_C^{phys}$ directly as SX/MX expressions. E0-3 sharing remains exact:
only free masters are decision variables and physical occurrences are gathered
from those masters. Derived conductances/matrices remain symbolic functions of
physical masters. CasADi supplies exact sparse AD of these expressions
\cite{Andersson2019CasADi,CasADiDocs2026}.

A second, optional transformed CasADi adapter may evaluate
$\Theta_C=\mathcal T(\rho)$ solely for transform/parity diagnostics. Production
IPOPT parameter estimation is not required to optimize $\rho$.

\subsection{Method-family responsibility map}
The frozen E0 architecture distinguishes model family from computational
backend:
\begin{center}
\begin{tabular}{p{0.28\textwidth}p{0.19\textwidth}p{0.22\textwidth}p{0.23\textwidth}}
\toprule
Method family & Explicit RC equations? & Primary backend & Parameter coordinate\\
\midrule
Pure black-box ML (MLP/RNN/GRU/LSTM) & No & PyTorch & neural weights\\
Pure Neural ODE & No explicit RC & PyTorch/Neuromancer & neural ODE weights\\
Inverse PINN--RC & Yes & PyTorch/Neuromancer & transformed $\rho\mapsto\Theta$\\
Classical differentiable RC ODE fitting & Yes & PyTorch/Neuromancer & transformed $\rho\mapsto\Theta$\\
Base PINODE & Yes & PyTorch/Neuromancer & transformed RC $\rho$ plus learned weights\\
EBP--PINODE & Yes & PyTorch/Neuromancer & transformed RC $\rho$ plus learned weights\\

\end{tabular}
\end{center}
Pure ML is intentionally outside the RC backend machinery. A pure Neural ODE is
an ODE model but need not contain RC parameters. Inverse-PINN/PINODE families
consume the RC compiler through PyTorch/Neuromancer. Deterministic optimization
consumes the same RC compiler through CasADi. Bayesian estimation consumes the
same physical RC equations through a numerical likelihood backend.

\section{E0-6N2: CasADi/IPOPT physical-coordinate nonlinear parameter-estimation interface}

E0-6 does not own a particular objective function, regularizer, HPO strategy, or
IPOPT option set. It does freeze the physical model interface required by the
later deterministic-optimization family.

Let $\Theta_f$ be free physical RC masters and let $X_{0:K}$ optionally be
shooting-state decision variables. A generic direct-transcription/multiple-
shooting NLP has the form
\[
\boxed{
\begin{aligned}
\min_{\Theta_f,X_{0:K}}\quad & J(\Theta_f,X_{0:K};Y^{obs},U)\\
\text{s.t.}\quad
&X_{k+1}-\Phi_{\Delta t_k}^{\mathcal M}
 (X_k,U_k;\Theta_f)=0,\\
&\ell_\Theta\le\Theta_f\le u_\Theta,\\
&c_{eq}(\Theta_f)=0,\\
&\ell_c\le c_{ineq}(\Theta_f)\le u_c,
\qquad k=0,\ldots,K-1.
\end{aligned}}
\]
A condensed/single-shooting formulation may eliminate $X_{1:K}$ and propagate
states internally; both formulations use the same E0-5 propagation map and the
same physical RC authority.

Examples of direct physical admissibility are
\[
R_e\ge R_{min}>0,\qquad C_i\ge C_{min}>0,
\]
\[

\section{E0-6R: Analytical derivatives and coordinate-consistent parameter sensitivities}

For
\[
f(x,T_B,Q;\Theta)=A(\Theta)x+B_T(\Theta)T_B+B_Q(\Theta)Q,
\]
the continuous state/input Jacobians are exactly
\[
\boxed{\frac{\partial f}{\partial x}=A},\qquad
\boxed{\frac{\partial f}{\partial T_B}=B_T},\qquad
\boxed{\frac{\partial f}{\partial Q}=B_Q}.
\]
These are backend-independent derivative oracles.

For a deterministic probe $v$, define the physical-coordinate scalar
\[
\ell_f(\Theta)=v^{\mathsf T}f(x,T_B,Q;\Theta).
\]
CasADi's production sensitivity is naturally
\[
\boxed{g_\Theta^C=\nabla_\Theta\ell_f.}
\]
PyTorch transformed training instead computes
\[
\boxed{g_\rho^T=\nabla_\rho\ell_f(\mathcal T(\rho)).}
\]
These gradients are not numerically equal because their coordinates differ.
The correct cross-coordinate relation is
\[
\boxed{
g_\rho^T
=J_{\mathcal T}(\rho)^{\mathsf T}g_\Theta^C,
\qquad
J_{\mathcal T}=\frac{\partial\Theta}{\partial\rho}.
}
\]
This chain-rule identity, rather than raw-gradient equality, is the mandatory
transformed-vs-physical parameter-sensitivity parity test. A CasADi transformed
reference adapter may additionally compute $\nabla_\rho\ell$ directly as a
secondary implementation diagnostic.

For a discrete propagation probe
\[
\ell_\Phi(\Theta)=v^{\mathsf T}\Phi_{\Delta t}(x,U;\Theta),
\]
the same physical-coordinate and chain-rule comparisons apply.

Finite differences are diagnostic only. In raw coordinates, the existing step
\[
\delta_j=\epsilon_{mach}^{1/3}(1+|\rho_j|)
\]
may be used. In physical coordinates, scale-aware perturbations must respect the
physical domain and are never the production gradient source.
