SCALEBRIDGE PHASE D D8.4 MLFLOW TRACKING LOCK
===============================================
Date: 2026-08-12

Scope
-----
D8.4 adds campaign-level MLflow tracking to Phase D without changing the
scientific meaning of Phase D datasets. Because the supplied direct input bundle
was still D8.2, this patch also includes the already-required D8.3 repeatable
ML/SciML lag support so the P1 lags 1/3/6 can coexist in one canonical run.

MLflow architecture
-------------------
One MLflow run per Phase D campaign execution.
No per-aggregation child runs by default.
No final data.parquet files uploaded to MLflow.
No 240 per-aggregation log files uploaded to MLflow.

Authoritative detailed provenance remains:
    phase_d_campaign_plan.json
    phase_d_campaign_run_manifest.json
    aggregation_run_registry.csv
    dataset_registry.csv
    failures.csv

CLI
---
    --mlflow
    --mlflow-experiment-name <name>
    --mlflow-run-name <name>
    --mlflow-strict

Tracking is opt-in. --mlflow-strict converts MLflow setup/logging failures into
Phase D failures. Without strict mode, tracking errors produce warnings and the
scientific Phase D workflow may continue.

Default experiment if none supplied:
    ScaleBridge_PhaseD_<campaign_id>

Semantic artifact root:
    <SCALEBRIDGE_GENERATED_DATA_ROOT>/mlflow_artifacts/phase_d/<campaign_id>/

Failure cleanup
---------------
If the process exits after an MLflow run starts but before normal finalization,
the tracker attempts to close the active run as FAILED through an atexit hook.
Normal completion closes FINISHED/FAILED according to Phase D campaign status.

D8.3 included
-------------
--ml-input-lag is repeatable.
Default remains [12] if omitted.
Every lag must be >= 1.
Duplicates are rejected.
ML configurations are policy x lag Cartesian product.
Opt/Bayes remains lag/horizon 1/1.
runner_configuration stores ml_input_lags.
